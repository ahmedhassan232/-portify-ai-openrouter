# Portify AI

Your CV. Your Story. Your Portfolio. Upload a CV (PDF/DOCX), pick a profession and a template, let AI structure the content, edit it live, and download a standalone website (ZIP). Fully bilingual: English (LTR) and Arabic (RTL) in the app **and** in every generated site.

No accounts. No database. Drafts live in your browser (IndexedDB + LocalStorage).

## Quick start
```bash
npm install
cp .env.example .env.local   # set OPENAI_API_KEY (and optionally OPENAI_MODEL)
npm run dev                  # builds the export stylesheet, then starts Next.js
```
Without `OPENAI_API_KEY` the app says so plainly and offers clearly-labelled **sample data** so you can explore the editor, templates and export. It never pretends AI worked.

Scripts: `npm run typecheck` · `npm run lint` · `npm test` · `npm run build`

## Deploy (Vercel)
1. Import the repo. 2. Add `OPENAI_API_KEY` (and `OPENAI_MODEL`). 3. Deploy. The build command already runs `build:export-css`, which generates `public/export/portfolio.css` (the stylesheet shipped inside exported sites).
Routes using AI: `maxDuration = 60` (needs a plan that allows it; lower it otherwise).

## How it works
`/` landing → `/upload` (server extracts text in memory, nothing stored) → `/profession` (+ portfolio language) → `/processing` (AI structured extraction, zod-validated) → `/templates` (12 live previews of **your** content; optional AI polish) → `/editor` (3 panels) → `/preview` → export.

- **One template system, two directions.** Templates are pure React components using logical Tailwind utilities (`ms/me/ps/pe/start/end`) and CSS variables for colour/fonts. Direction and fonts come from the *portfolio* language, independent of the UI language. A test fails if a physical `ml/mr/pl/pr/text-left/right` class sneaks in.
- **i18n:** `src/i18n/translations/{en,ar}.json` (315 keys), typed keys (`TKey`) so a missing key is a compile error; `tests/i18n.test.ts` enforces parity and placeholders. Language saved in LocalStorage; an inline script sets `lang/dir` before first paint.
- **AI safety:** facts only; CV text treated as untrusted; strict JSON schema; zod validation; and a server-side **merge guard** so polish/translation can only reword (company names, dates, URLs, skills, entry counts come from your original data).
- **Export:** the same React templates are rendered to static HTML in the browser (`renderToStaticMarkup`), so the export matches the preview. ZIP = `index.html` (+ `index-<lang>.html` and a language toggle when a second version exists), `styles.css`, `script.js`, `assets/`, `README.md`. Also a single-file HTML download.
- **Privacy:** uploaded files are parsed in memory and discarded. When AI runs, the extracted text is sent to OpenAI: the UI and `/privacy` say so.

## Known limits (honest list)
- Scanned PDFs need OCR: not implemented; the app says so instead of producing an empty portfolio.
- Exported sites load fonts from Google Fonts (system fallback offline). Self-hosting font files needs network at build time.
- UI primitives are hand-written (shadcn-style) rather than generated by the shadcn CLI. UI font is Inter/Cairo/IBM Plex Sans Arabic (Geist not used).
- Rate limiting is in-memory per server instance; use Redis/Upstash if you scale out.
- Visual/responsive QA must be done in a browser: see `docs/QA-CHECKLIST.md`.
